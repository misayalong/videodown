## Chrome 合成数据验证

仍使用真实扩展构建与 Chrome，模拟页面/API/媒体输入，避免依赖外站状态：

- 实际 YouTube MAIN 桥接 → 格式转换 → 公共菜单 → Service Worker → offscreen → OPFS → mediabunny → Chrome 下载完整链路通过。
- 使用 FFmpeg 生成两秒纯色视频和正弦音频；合并产物 21,419 字节，ffprobe 确认 H.264 320×180 + AAC，时长 2.00 秒，完成后 `busy` 为空。菜单中的 1080p 为合成 API 标签，不代表测试视频的真实像素尺寸。
- 延迟合成媒体读取后，在全屏菜单显示「合并中 0%」及取消入口；点击取消后活动条目恢复、`busy` 清空，退出全屏后宿主回到页面根节点。
- Shorts 合成页面验证活动 reel 的定位：视频元素纵向偏移到容器外时，按钮仍以容器顶部和画面水平范围定位，处于可见状态。
- X 合成双视频响应在同一菜单中分别显示「视频 1 / 720p」和「视频 2 / 360p」，Escape 能关闭菜单。

模拟测试最初受 YouTube 的站点 Service Worker 干扰；改用独立配置阻止站点 Service Worker。离屏页面的媒体读取用测试会话内的 fetch 替身提供合成字节；正式源码和构建中均不包含这些替身。

测试截图、脚本和下载样本保留在本地忽略目录 `output/playwright/`，未纳入扩展构建。

## 手工复验

1. 加载 `dist/`，刷新两平台页面，悬停视频并下载低清晰度样本。
2. 在有双轨选项的 YouTube 页面选择高清格式，检查进度、取消、重开任务及最终音画。
3. 在另一标签页同时发起合并，确认忙碌提示；同时可继续发起直链下载。
4. 验证 Shorts、全屏、页面导航以及 X 多视频推文的定位和菜单分组。
5. `npm test` 可重新执行全部自动化验证。
